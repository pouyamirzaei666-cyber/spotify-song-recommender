# برگه واقعیت‌های پروژه — برای دفاع در مصاحبه

## آنچه در نوت‌بوک فارسی مشاهده شد
- دیتاست اولیه: 2,110,316 ردیف و 25 ستون.
- پس از حذف ردیف‌های ناقص و تکراری‌گیری بر اساس `spotify_id`: 24,975 آهنگ یکتا. برای رکوردهای فاقد شناسه، زوج `(name, artists)` معیار جایگزین است.
- نمونه ثابت: 12,000 ردیف با `random_state=42`.
- ویژگی‌ها: danceability, energy, loudness, speechiness, acousticness, instrumentalness, liveness, valence, tempo.
- StandardScaler برای مقیاس‌بندی ویژگی‌ها.
- DBSCAN با `eps=1.9`, `min_samples=12`, `n_jobs=-1`.
- خروجی DBSCAN با CSV ارسالی در 2026-11-20: cluster 0 = 11,635; cluster 1 = 12; cluster 2 = 7; noise (-1) = 346.
- تابع پیشنهاد اصلی نوت‌بوک از cosine similarity و در صورت امکان محدودیت خوشه استفاده می‌کرد.
- در خروجی نمونه `Die With A Smile`، پیشنهادهای چندزبانه دیده شدند؛ بنابراین نزدیکی عددی ویژگی‌ها به‌تنهایی کیفیت موسیقایی را ثابت نمی‌کند و ارزیابی انسانی هنوز لازم است.

## اصلاحات نسخه بسته‌بندی‌شده انگلیسی
- DBSCAN صرفاً برای تحلیل اکتشافی باقی مانده و در فیلتر پیشنهادها دخالت نمی‌کند.
- بازیابی پیشنهادها با NearestNeighbors و فاصله Euclidean در فضای ویژگی‌های StandardScaler انجام می‌شود.
- خروجی پیشنهادهای نرم‌افزار شامل نام آهنگ، هنرمند و feature distance است؛ ستون cluster به‌عنوان خروجی اصلی نمایش داده نمی‌شود.
- جست‌وجو عنوان و هنرمند را با تطبیق متنی literal و بدون regex بررسی می‌کند.
- انتخاب دقیق قطعه از بین نتایج هم‌نام به کاربر سپرده می‌شود.
- تست‌های واحد برای جست‌وجو، رتبه‌بندی فاصله، حذف هنرمند و index نامعتبر نوشته شده‌اند؛ هر ۵ تست در این بسته اجرا شدند و موفق بودند.

## آنچه هنوز اثبات نشده است
- کیفیت موسیقایی پیشنهادها در مقایسه با داوری شنوندگان.
- بهبود واقعی تجربه کاربر یا نرخ تعامل.
- دقت توصیه‌گر یا افزایش رضایت/نگهداشت کاربر.
- مجوز بازتوزیع دیتاست.
- ارزیابی کیفیت موسیقایی توسط شنوندگان یا معیارهای Precision@K / NDCG@K.
- اجرای تصویری واقعی رابط Streamlit در محیط فعلی بسته‌بندی؛ منطق برنامه و نحو فایل‌ها بررسی شده‌اند، اما اسکرین‌شات نسخه جدید باید پس از اجرای محلی گرفته شود.
