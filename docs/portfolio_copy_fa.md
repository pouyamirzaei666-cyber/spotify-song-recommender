# متن آماده نمونه‌کار فارسی — Spotify Song Recommender

> این متن برای ثبت در کارلنسر، پونیشا و پلتفرم‌های مشابه آماده شده است. ادعاها عمداً به قابلیت‌هایی محدود شده‌اند که در نوت‌بوک و نسخه بسته‌بندی‌شده وجود دارند.

## عنوان نمونه‌کار
**طراحی سیستم پیشنهاد آهنگ مشابه با Python و Machine Learning**

## عنوان کوتاه جایگزین
**موتور پیشنهاد موسیقی مبتنی بر تحلیل ویژگی‌های صوتی**

## خلاصه کوتاه
طراحی یک سیستم پیشنهاددهنده موسیقی که با تحلیل ۹ ویژگی صوتی هر قطعه، نزدیک‌ترین آهنگ‌ها را در فضای ویژگی‌های استانداردشده پیدا می‌کند. پروژه شامل آماده‌سازی داده، تحلیل خوشه‌بندی، موتور جست‌وجوی نزدیک‌ترین همسایه‌ها و رابط کاربری Streamlit است و یک API مبتنی بر FastAPI نیز برای توسعه و اتصال به سایر نرم‌افزارها دارد.

## توضیحات کامل
### مسئله
پیدا کردن موسیقی جدید با ویژگی‌های صوتی نزدیک به یک آهنگ مشخص، یکی از کاربردهای سیستم‌های پیشنهاددهنده است. در این پروژه، به‌جای اتکا به نام آهنگ یا محبوبیت آن، ویژگی‌های عددی صوتی قطعه برای بازیابی آهنگ‌های نزدیک مقایسه می‌شوند.

### راهکار پیاده‌سازی‌شده
- پاک‌سازی داده‌ها، مدیریت مقادیر ناقص و حذف تکراری‌ها بر اساس نام آهنگ و هنرمند
- استفاده از ۹ ویژگی صوتی: Danceability، Energy، Loudness، Speechiness، Acousticness، Instrumentalness، Liveness، Valence و Tempo
- استانداردسازی ویژگی‌ها با `StandardScaler`
- تحلیل اکتشافی خوشه‌ها با `DBSCAN`
- ساخت موتور پیشنهاددهنده با `NearestNeighbors` و فاصله اقلیدسی در فضای ویژگی‌های استانداردشده
- جست‌وجوی قطعه بر اساس عنوان یا نام هنرمند و امکان حذف آثار همان هنرمند از پیشنهادها
- طراحی رابط تعاملی با `Streamlit`
- ارائه API اختیاری با `FastAPI`

### داده و نتیجه تحلیل
در CSV اصلی، ۲٬۱۱۰٬۳۱۶ ردیف وجود داشت. پس از پاک‌سازی و حذف شناسه‌های تکراری Spotify، تعداد ۲۴٬۹۷۵ آهنگ یکتا باقی ماند. برای اجرای مدل، نمونه‌ای ۱۲٬۰۰۰ تایی با `random_state=42` انتخاب شد.

در اجرای مجدد DBSCAN روی همین CSV، خوشه صفر ۱۱٬۶۳۵ آهنگ، خوشه یک ۱۲ آهنگ، خوشه دو ۷ آهنگ و ۳۴۶ آهنگ نویز (`-1`) داشتند. به دلیل نامتوازن بودن خوشه‌ها، DBSCAN صرفاً برای تحلیل اکتشافی استفاده می‌شود و فیلتر پیشنهادها نیست.

### فناوری‌ها
Python، Pandas، NumPy، Scikit-learn، StandardScaler، DBSCAN، NearestNeighbors، Streamlit، FastAPI، Joblib و CSV

### نقش و مسئولیت‌ها
تحلیل و آماده‌سازی داده، انتخاب ویژگی‌ها، ساخت و بررسی الگوریتم پیشنهاددهنده، توسعه رابط کاربری و آماده‌سازی API.

### محدودیت فنی شفاف
فاصله کمتر به معنی نزدیک‌تر بودن بردارهای عددی ویژگی‌های صوتی است؛ این عدد درصد دقت، احتمال پسندیدن آهنگ یا تضمین شباهت از نظر شنونده نیست. در بررسی نمونه‌های واقعی، پیشنهادهای چندزبانه دیده شدند؛ بنابراین کیفیت موسیقایی هنوز با داده مرجع انسانی یا آزمایش کاربری ارزیابی نشده است. مدل فعلی متن ترانه، ژانر، ملودی، روابط هنرمندان یا فایل خام صوتی را مستقیماً تحلیل نمی‌کند.

## ترتیب پیشنهادی تصاویر
1. `cover.png` — کاور گرافیکی حرفه‌ای پروژه؛ تصویر معرفی است، نه اسکرین‌شات نرم‌افزار.
2. `pipeline.png` — دیاگرام فرآیند فنی پروژه.
3. یک اسکرین‌شات تازه از نسخه بسته‌بندی‌شده Streamlit، بعد از اجرای موفق آن با دیتاست اصلی. این تصویر هنوز باید توسط صاحب پروژه گرفته شود.

فایل `reference_baseline_user_app.png` فقط تصویر مرجع نسخه قبلی است؛ به‌دلیل نمایش ستون خوشه و خروجی‌های نمونه‌ای که هنوز از نظر موسیقایی ارزیابی نشده‌اند، توصیه نمی‌شود آن را به‌عنوان تصویر نهایی UI در رزومه عمومی قرار دهی.

## متن کوتاه برای معرفی شفاهی
«در این پروژه یک سیستم پیشنهاد موسیقی مبتنی بر محتوا طراحی کردم. ابتدا داده‌ها را پاک‌سازی کردم، سپس ۹ ویژگی صوتی را استانداردسازی کردم و با Nearest Neighbors آهنگ‌هایی را پیدا می‌کنم که از نظر این ویژگی‌ها به آهنگ انتخاب‌شده نزدیک‌ترند. DBSCAN را هم برای تحلیل ساختار داده بررسی کردم، اما چون خوشه‌ها نامتوازن بودند، آن را محدودکننده پیشنهادها قرار ندادم. رابط کاربری با Streamlit و API با FastAPI آماده شده است. این سیستم شباهت عددی ویژگی‌های صوتی را می‌سنجد و هنوز ادعای تشخیص سلیقه یا دقت موسیقایی ندارد.»
